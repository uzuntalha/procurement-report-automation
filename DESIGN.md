## 0. One-line summary

A bilingual (EN/TR), local web-based automation tool that turns a synthetic
procurement workbook into an executive-ready weekly management deck (`.pptx`)
for any selected week. Portfolio piece aimed at **strategy / consulting** roles.

---

## 1. Why this project exists (the story / CV message)

- **Observation:** In corporate procurement teams, a weekly management PowerPoint
  is commonly prepared **manually** from large Excel files — who bought how much within their own approval limit vs.
  what went to management approval, which suppliers, domestic/foreign split, etc.
- **Insight:** This recurring manual reporting is automatable end-to-end.
- **Constraint:** No real company template or data is used.
  → Everything in this project is **100% synthetic / fictional**. No real data,
    no real template, no company branding.
- **Positioning:** NOT "I became a software developer." Instead:
  *"I spotted a recurring manual process, quantified its cost, and automated it
  end-to-end."* This is a **mini consulting case study**. Code is the proof, not
  the point. Target audience: strategy departments & consulting firms
  (international → English-first).

## 4. Data model — synthetic workbook (6 sheets)

All fictional/synthetic. Generated by `generate_sample_data.py`. ~1 year of data.

### Sheet 1 — `Satın Almalar` (transactions / fact table)
`PR No`, `PO No`, `Kalem No`, `Talep Tarihi`, `Sipariş Tarihi`,
`Teslim Tarihi (Planlanan)`, `Gerçekleşen Teslim Tarihi` (blank for open orders),
`Departman`, `Sorumlu Kodu`, `Tedarikçi Kodu`, `Kategori`, `Malzeme Açıklaması`,
`Miktar`, `Birim`, `Birim Fiyat`, `Liste Fiyatı`, `Tutar`, `Para Birimi`,
`Ödeme Yöntemi Kodu`, `Onay Tipi`, `Durum`, `Aciliyet`.

### Sheet 2 — `Tedarikçiler` (master)
`Tedarikçi Kodu`, `Tedarikçi Adı`, `Ülke`, `Menşei (Yurt İçi/Dışı)`,
`Varsayılan Ödeme Vadesi`, `Tedarikçi Segmenti (Stratejik/Onaylı/Yeni)`.

### Sheet 3 — `Sorumlular & Limitler` (master)
`Sorumlu Kodu`, `Ad Soyad`, `Departman`, `Satın Alma Türü`, `Onay Limiti (TRY)`.
→ Purchase types: Elektronik, Fason, İç Satın Alma, Kurumsal Satın Alma, Mekanik.

### Sheet 4 — `Ödeme Yöntemleri` (master)
`Ödeme Yöntemi Kodu`, `Yöntem` (Peşin / Vadeli 30-60-90 / Akreditif (LC) /
Banka Havalesi / Çek), `Vade (gün)`.

### Sheet 5 — `Kur Tablosu`
`Tarih`, `Para Birimi`, `TRY Kuru`.

### Sheet 6 — `Bütçe`
`Dönem (Ay)`, `Satın Alma Türü`, `Bütçe (TRY)`.

### Business rules the tool derives (not stored as raw truth)
- **Onay Tipi**: if `Tutar (TRY)` > buyer's `Onay Limiti` → "Yönetim Onayı", else "Limit İçi".
  (Stored in data too for realism, but tool can recompute — shows rule in code.)
- **TRY conversion**: each transaction → TRY via date-appropriate rate from `Kur Tablosu`.
- **Savings**: `(Liste Fiyatı − Birim Fiyat) × Miktar`. Some rows have list = unit (no saving).
- **OTD / lead time**: `Sipariş Tarihi − Talep Tarihi`; late = actual delivery > planned.
- **Satın Alma Türü**: joined from buyer master.

Each slide uses the visualization that fits its data. One consistent palette/font.
Rendered EN or TR based on the report-language selector. (v1 shipped 13 slides;

## 6. Tool behavior (the automation)

1. User uploads a workbook (or the pre-loaded sample is used in the live demo).
2. **Schema validation**: checks 6 sheets + required columns exist; friendly,
   specific errors (e.g. "'Satın Almalar' sheet is missing the 'Tutar' column").
   TR/EN column headers both accepted via a mapping table. No fuzzy matching.
3. User picks a **week / date range** and a **report language (EN/TR)**.
4. Tool joins sheets, derives approval type from limits, converts to TRY via rates,
   computes all metrics, renders the matplotlib charts, assembles the `.pptx`.
5. User downloads the deck.

## 11. v2 enhancements (2026-08-31, after web research on enterprise CPO reports)

Motivation: v1 weekly comparison was too thin (only KPI-card deltas) and the deck
lacked the enterprise metrics a real CPO report carries. Researched standard
procurement KPIs/benchmarks (Ivalua, Suplari, Precoro, NIGP) and added:

- **Data model:** two new transaction fields — `Sözleşme Kapsamı`
  (Sözleşmeli/Sözleşmesiz) and `Kusurlu Teslim` (Evet/Hayır). Generator seeds
  ~80% on-contract and ~5% defect-on-closed. Added `--seed` CLI flag.
- **Week-over-week everywhere:** new **Week-over-Week Scorecard** slide (6 KPIs
  this vs last week) + Spend-by-Type turned into this-vs-last grouped bars.
- **New enterprise slides:** Contract Compliance & Maverick Spend (with
  best-in-class benchmark gauges: SUM ≥80%, maverick ≤10%), Supplier Scorecard
  (spend × OTD × defect × segment table), Payment Terms & DPO. Supplier Pareto
  slide gained a tail-spend caption.
- **Deck grew 13 → 17 slides.** All verified end-to-end (tests pass, EN/TR build,
  live app redeployed). README previews re-rendered.
- **Robustness proven:** pipeline tested against a different-seed workbook AND an
  English-headers workbook (exercises the TR/EN column mapping).
